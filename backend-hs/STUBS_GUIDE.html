AlgoRoute Haskell — Stub Fill-In Order

A checklist for turning the 18 stubbed .hs files into a working backend, in dependency order. Pairs with haskell-rewrite-plan.html (the what) and TUTOR.md (the how to learn it).

Golden rule — bottom-up. Fill in pure, dependency-free code first; leave IO and HTTP for last. Every stub already has its type signature, imports, and a TODO pointing at the Go source it ports from. Replace each undefined with a real body, one module at a time, and keep the thing compiling as you go.

How each stub is laid out

  • Signature + data types are done for you — the plan says "start with types," so the records, sum types, and function signatures are already written.
  • Bodies are undefined with a -- TODO block naming the Go function to port and sketching the approach.
  • Layering note: Coord/BBox live in Geo.Types (not Graph.hs as the plan's §3.1 shows) — the .cabal gives us a Geo.Types module and it matches the Go package split. Everything imports from there.
Pure — no IO, TDD directly IO / effectful Wiring / HTTP

The order

1

Geo.Types + Geo.Distance

Pure
Files: src/Geo/Types.hs, src/Geo/Distance.hs · Go: geo/coords.go, geo/bbox*.go, geo/distance.go

Teaches: records, deriving, degrees→radians math. No dependencies at all — the true bottom of the stack.

Do: contains, approxAreaKm2, bboxFromCoords, then the Haversine distanceMeters.

Checkpoint: distanceMeters matches the Go DistanceMeters results to within a few metres in the REPL.
2

Graph

Pure
File: src/Graph.hs · Go: graph/network.go, graph/snap.go

Teaches: the immutable-value mindset — "mutate the network" becomes "return a new Network." Data.Map.Strict, Either for validation.

Do: addNode, addEdge, neighbours, nearestNode.

Checkpoint: you can build a small Network by hand and nearestNode snaps a coordinate to the right vertex.
3

Routefinding.Types + Routefinding.Heap

Pure
Files: src/Routefinding/Types.hs, src/Routefinding/Heap.hs · Go: routefinding/router.go, routefinding/indexed_heap.go

Teaches: sum types for results/errors; a persistent indexed min-heap (Seq + position Map) replacing an in-place slice + index map.

Do: parseAlgorithm; then member, insert, popMin, decreaseKey with private siftUp/siftDown/swap.

The heap is the fiddliest pure module — write the HSpec test first and keep the entries/positions maps in sync on every swap. This is the one place a subtle bug will haunt Dijkstra later.

Checkpoint: property test — repeatedly popMin yields priorities in non-decreasing order; decreaseKey re-orders correctly.
4

Routefinding.Dijkstra → Routefinding.AStar

Pure
Files: src/Routefinding/Dijkstra.hs, src/Routefinding/AStar.hs · Go: dijkstra.go, astar.go

Teaches: the mindset shift — the Go while-loop that mutates costs/parents/heap becomes a tail-recursive go helper whose loop state is its arguments.

Do: finish dijkstra first (the stub sketches the go/relax/reconstruct shape), get it green, then do astar — which changes exactly one thing: heap priority g → g + haversine.

Checkpoint: both pass on a hand-built Network, and you can explain why A*'s only change is the heuristic term.
5

Overpass.Types

Pure (JSON)
File: src/Overpass/Types.hs · Go: api/overpass/client.go

Teaches: sum types vs Go's string-tagged struct; a hand-written FromJSON that reads the "type" field to pick NodeElement vs WayElement.

Do: the FromJSON Element instance, mkResponse (derive the ways list + node index), elemTag.

Checkpoint: parsing testdata/sample_overpass.json yields the right NodeElement/WayElement values. Reuse the Go fixture — don't invent a new one.
6

Mapping

Pure
File: src/Mapping.hs · Go: mapping/road_mapper.go

Teaches: foldl' replacing nested mutating loops — fold over ways, each way folds over its consecutive node pairs, accumulating into a Network.

Do: buildNetwork plus the oneway predicates and consecutivePairs.

Checkpoint: the fixture produces the same node count, edge count, and oneway handling as the Go mapping tests.
7

Geo.Geocode → Geo.Suggest → Geo.Reverse

IO
Files: src/Geo/Geocode.hs, src/Geo/Suggest.hs, src/Geo/Reverse.hs · Go: geo/geocode.go, suggest.go, reverse.go

Teaches: your first ExceptT GeoError IO; http-client (Manager, requests, User-Agent header). Do Geocode first — the other two are the same shape.

Do: the pure *URL builders (unit-test these without a network), then the three fetchers.

Nominatim returns lat/lon as JSON strings. Parse with read @Double . unpack — same as Go's strconv.ParseFloat.

Checkpoint: a geocode returns Right coord for a real address and Left err on failure; suggest skips unparseable hits instead of failing.
8

Overpass.Client

IO
File: src/Overpass/Client.hs · Go: api/overpass/fetch.go

Teaches: POST with a form body, a 30 s timeout, and the 10 MB response cap; reusing the FromJSON Response from step 5.

Do: buildQuery (pure — test it), then fetchFromAPI and the loadFromFile helper.

Checkpoint: buildQuery emits the expected Overpass QL string; loadFromFile round-trips the fixture.
9

Services.Cache → Services.Routing

IO + concurrency
Files: src/Services/Cache.hs, src/Services/Routing.hs · Go: services/network_cache.go, address_routing.go

Teaches: STM/TVar vs a sync.RWMutex; the Env record (scoped-singleton Manager+Cache); and the payoff — the 7-step pipeline as one ExceptT AppError IO do-block that short-circuits on the first Left.

Do: newCache/lookupCache/insertCache, then newEnv, routeByAddress, runRouter.

Checkpoint: cache hit/miss works; the pipeline returns typed errors (AreaTooLarge, NoRoadsFound, …) matching the Go behavior.
10

API.Types → API.Handlers

HTTP
Files: src/API/Types.hs, src/API/Handlers.hs · Go: server/server.go, server/handlers.go

Teaches: Servant's type-level API (:>, ReqBody, QueryParam, :<|>); handlers as ExceptT ServerError IO; CORS via wai-cors.

Do: in API.Types, the snake_case JSON instances (one shared Options). In API.Handlers, server, the three handlers (rename the _handle* stubs once wired), appErrorToServant, and corsApp.

Keep JSON field names byte-for-byte identical to the Go tags (distance_meters, visited_nodes, display_name) — the existing frontend depends on them.

Checkpoint: hspec-wai tests hit all three endpoints and match the existing JSON contract.
11

app/Main.hs

Wiring
File: app/Main.hs · Go: main.go

Teaches: optparse-applicative flags, warp run, and the #ifdef LAMBDA split (why the .cabal has two executables). Fill the non-Lambda branch first.

Do: app, cliParser, both mains.

Checkpoint: cabal run backend-hs-local -- --port 8080 serves the real API and the existing frontend talks to it unchanged.

Dependency graph (why this order)

Each module only imports things above it, so filling top-to-bottom means you never call an undefined you haven't reached yet:

Geo.Types ── Geo.Distance
   │              │
   ▼              ▼
 Graph ◄──────────┘
   │
   ├── Routefinding.Types ── Routefinding.Heap ── Dijkstra ── AStar
   │
   ├── Overpass.Types ── Overpass.Client ── (http-client)
   │                          │
   └── Mapping ◄──────────────┘
        │
 Geo.Geocode/Suggest/Reverse ─┐
        │                     │
        ▼                     ▼
 Services.Cache ──► Services.Routing (Env, pipeline)
                          │
                    API.Types ──► API.Handlers
                                       │
                                   app/Main.hs

The build/feedback loop

cd backend-hs
nix develop                 # toolchain shell — first thing, every session

cabal build                 # compile everything
cabal repl backend-hs       # load the lib, poke a function, :reload after edits
cabal test                  # HSpec suite (once you add test/*Spec.hs)
fourmolu -i src app         # format in place
hlint src app               # lint

TDD each module (per CLAUDE.md + TUTOR.md): add test/<Module>Spec.hs, write a failing assertion, watch it fail, then replace the undefined with the minimum that passes. hspec-discover auto-collects any *Spec under test/ — no wiring needed. Reuse the Go testdata/*.json fixtures as-is.

When a stub won't compile

SymptomLikely cause
Could not find module …Missing build-depends or exposed-modules entry in backend-hs.cabal — the .cabal is the source of truth. Re-enter/reload the dev shell after editing it.
Ambiguous occurrence 'lat'The shared-field-name gotcha. The stubs already turn on DuplicateRecordFields + OverloadedRecordDot; access via coord.lat to disambiguate by type. (See TUTOR.md §1a.)
Defined but not used warningsExpected while stubs are still undefined — harmless until the module is finished. The _-prefixed helper/handler stubs are named that way on purpose to suppress the warning.
Servant type mismatchHandler shape doesn't match the API type. The compiler is checking your contract — read the expected vs actual type, don't fight it.
